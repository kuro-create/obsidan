# 🧩 **各ディレクトリの役割（技術者向けに最適化した説明）**

## 📂 **src/**

**ソースコードを置く場所（教材の本体）**

- OpenMP の学習ステップごとにコードを整理
    
- VSCode で開くときの “作業の中心”
    
- Claude Code や Git 管理にも最適
    

例：

コード

```
src/step1/hello_parallel.c
src/step2/parallel_for.c
src/step3/reduction.c
```

**ポイント：** あなたのように「構造化された学習」を重視する人にとって、 ステップごとにフォルダを分けるのは理解効率が非常に高い。

## 📂 **src/step1/, step2/, step3/...**

**学習ロードマップの各ステップを独立させるためのフォルダ**

- STEP1：並列処理の基礎（Hello Parallel）
    
- STEP2：parallel / parallel for
    
- STEP3：reduction / schedule
    
- STEP4：性能測定
    
- STEP5：応用（行列・画像・粒子）
    

**メリット：**

- 「どの段階のコードか」が一目でわかる
    
- 後から復習しやすい
    
- 実験コードを壊しても他のステップに影響しない
    
- Git で差分管理しやすい
    

## 📂 **build/**

**コンパイル結果（実行ファイル）を置く場所**

- `src/` を汚さないための “成果物置き場”
    
- Makefile を使う場合はここにバイナリを出力
    
- 実行ファイルだけをまとめて管理できる
    

例：

コード

```
build/hello_parallel
build/parallel_for
build/reduction
```

**ポイント：** あなたのように「美しいディレクトリ構造」を好むタイプには、 **src と build を分離する構成が最も合理的**。

## 📄 **Makefile（任意）**

**ビルドを自動化する設定ファイル**

- `make` だけでコンパイルできる
    
- `-fopenmp` や `-O2` などのオプションを統一管理
    
- ステップごとにターゲットを作れる
    

例：

コード

```
make step1
make step2
make all
```

**ポイント：** OpenMP は毎回 `-fopenmp` を付ける必要があるため、 Makefile で統一するとミスがなくなる。
