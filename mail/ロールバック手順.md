
# 結論：WordPress サーバ側のロールバックは「Postfix の設定ファイルだけ戻せば完了」

必要なのは **Postfix の 2 ファイル + sasl_passwd** のバックアップだけです。

- `/etc/postfix/main.cf`
    
- `/etc/postfix/master.cf`（変更していれば）
    
- `/etc/postfix/sasl_passwd`（平文）
    
- `/etc/postfix/sasl_passwd.db`（自動生成）
    

これらを戻せば、**完全に元の状態に戻ります**。

DKIM サーバ側は一切触らないので、ロールバック不要です。

# 🧭 **ロールバック手順（WordPress サーバ側のみ）**

以下は **実際に使える手順書**です。

## 🟦 Step 1：変更前にバックアップを取る（必須）

コード

```
sudo cp /etc/postfix/main.cf /etc/postfix/main.cf.bak
sudo cp /etc/postfix/master.cf /etc/postfix/master.cf.bak
sudo cp /etc/postfix/sasl_passwd /etc/postfix/sasl_passwd.bak 2>/dev/null
```

これで **いつでも戻せる状態**になります。

## 🟦 Step 2：587 + SASL の設定を投入

（これは前の手順で説明済み）

## 🟦 Step 3：問題が発生した場合のロールバック（最重要）

### ① Postfix を停止

コード

```
sudo systemctl stop postfix
```

### ② バックアップを戻す

コード

```
sudo cp /etc/postfix/main.cf.bak /etc/postfix/main.cf
sudo cp /etc/postfix/master.cf.bak /etc/postfix/master.cf
sudo cp /etc/postfix/sasl_passwd.bak /etc/postfix/sasl_passwd 2>/dev/null
```

### ③ sasl_passwd を再ハッシュ化

コード

```
sudo postmap /etc/postfix/sasl_passwd
```

### ④ Postfix を再起動

コード

```
sudo systemctl restart postfix
```

### ⑤ ログを確認

コード

```
sudo tail -f /var/log/mail.log
```

これで **完全に元の状態に戻ります**。

# 🧠 **ロールバックが Postfix 側だけで完結する理由**

あなたの構成は：

コード

```
WordPress サーバ（Postfix）
        ↓
DKIM サーバ（Postfix + opendkim）
```

DKIM サーバ側は：

- DKIM 署名
    
- SPF
    
- DMARC
    
- submission（587）
    
- SMTP AUTH
    

これらは **WordPress サーバの設定変更とは独立**しています。

つまり：

> **WordPress サーバ側の Postfix を元に戻すだけで、配送経路は完全に元通りになる。** **DKIM サーバ側は一切ロールバック不要。**

### ✔ DKIM 側の設定は配送経路に依存しないためロールバック不要

# 🎯 結論（最重要）

### ✔ `sasl_passwd` を変更した場合

→ **バックアップを戻す必要がある**

### ✔ `sasl_passwd` を変更していない場合

→ **ロールバック不要**

### ✔ `.db` ファイルは自動生成されるので、戻す必要なし

→ **平文ファイルだけ戻せばよい**

# 🧩 sasl_passwd のロールバックが必要になるケース

以下のような場合はロールバック対象になります：

- リレー先ホスト名を変更した
    
- 認証ユーザー名を変更した
    
- パスワードを変更した
    
- 587 → 25 などポート番号を変更した
    
- リレー先を別サーバに切り替えた
    

つまり **sasl_passwd の内容に変更があった場合のみ** ロールバックが必要。

# 🧩 sasl_passwd のロールバック手順（実際に使える形）

### ① Postfix を停止

コード

```
sudo systemctl stop postfix
```

### ② バックアップを戻す

コード

```
sudo cp /etc/postfix/sasl_passwd.bak /etc/postfix/sasl_passwd
```

### ③ ハッシュを再生成

コード

```
sudo postmap /etc/postfix/sasl_passwd
```

### ④ 権限を戻す（安全のため）

コード

```
sudo chmod 600 /etc/postfix/sasl_passwd*
```

### ⑤ Postfix を再起動

コード

```
sudo systemctl restart postfix
```

これで **完全に元の状態に戻ります**。

# 🧠 なぜ `.db` を戻す必要がないのか？

理由：

- `.db` は **postmap が自動生成するバイナリファイル**
    
- 平文ファイル（sasl_passwd）が正しければ、 **postmap で常に正しい .db が生成される**
    

つまり：

> **ロールバック対象は平文の** `/etc/postfix/sasl_passwd` **のみ**

# 🟦 逆に、ロールバック不要なケース

以下の場合は **sasl_passwd のロールバックは不要**：

- main.cf のみ変更した
    
- relayhost の設定だけ変更した
    
- TLS 設定だけ変更した
    
- opendkim 側の設定を変更した（今回対象外）
    

つまり **sasl_passwd を触っていなければロールバック不要**。

# 🔥 最終まとめ（孝汰さん向けに最適化）

- **sasl_passwd は “変更したときだけ” ロールバック対象**
    
- ロールバックは **平文ファイルを戻して postmap するだけ**
    
- `.db` は自動生成されるので戻す必要なし
    
- DKIM サーバ側はロールバック不要（今回の構成では完全に独立）
