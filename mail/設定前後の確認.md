587/TLS でリレー先に接続できるか確認事態は、relayhostの設定入れる前でもできますよね

結論：**はい、587/TLS の疎通確認（openssl s_client）は、relayhost を Postfix に設定する前でも問題なく実行できます。**

むしろ **設定前に疎通確認するのが正しい手順** です。 理由と、どういう意味を持つのかを構造的に整理します。

# 🎯 結論（最重要）

- **openssl s_client による 587/TLS の疎通確認は Postfix と無関係**
    
- relayhost を設定する前でも、後でも、いつでも実行できる
    
- これは「ネットワーク・TLS・SMTP AUTH が使えるか」を確認するためのテスト
    

つまり：

> **Postfix の設定前に疎通確認 → 問題なければ Postfix に relayhost を設定 → 動作確認** という順番が最も安全で確実。

# 🧠 なぜ relayhost 設定前でも疎通確認できるのか？

理由は簡単で：

- openssl s_client は **Postfix を経由しない**
    
- 直接「あなたの WordPress サーバ → DKIM サーバ（587）」に接続するだけ
    

つまり、Postfix の設定とは完全に独立したテスト。

# 🧩 疎通確認で分かること

コード

```
openssl s_client -connect dkim-mail.example.com:587 -starttls smtp
```

これで確認できるのは：

### ✔ 1. 587番ポートが開いているか

→ firewall / port forwarding / master.cf の設定が正しいか

### ✔ 2. STARTTLS が有効か

→ `250 STARTTLS` が返るか

### ✔ 3. TLS が確立できるか

→ 証明書情報が表示されるか

### ✔ 4. AUTH が有効か

→ `250 AUTH LOGIN PLAIN` が返るか

これらは **Postfix の relayhost 設定とは無関係**。

# 🧩 逆に、relayhost 設定後でないと確認できないこと

relayhost を設定しないと確認できないのは：

### ✔ Postfix が 587/TLS で接続できるか

### ✔ SASL 認証が成功するか

### ✔ メールがリレー先に渡るか

### ✔ DKIM サーバが署名して Gmail に届くか

これらは **Postfix の設定が必要**。
